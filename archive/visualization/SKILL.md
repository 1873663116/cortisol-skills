# 可视化

先确定希望读者看见的关系，再确认目标输出表面能够直接呈现或交付哪些载体。工具可用只代表能够生成结果；选择载体前，还要确认结果能够直接呈现，或者能够作为用户可访问的 Artifact 交付。优先直接呈现；交付能力不明确时，选择目标输出表面已经确认支持的载体。文字已经足够时，不为装饰而画图。

## 选择载体

| 载体 | 可用条件 | 适合的表达 |
|---|---|---|
| Mermaid | 目标输出表面支持 Mermaid 渲染 | 结构明确、需要随文本维护的流程、时序、状态、层级和对象关系 |
| SVG | 目标输出表面支持 SVG，或能够交付 SVG Artifact | 需要精确布局、定制图形或较高视觉完成度的静态图示 |
| Excalidraw | 工具可用，并且目标输出表面能够呈现其结果，或用户明确要求 | 自由空间组织、手绘标注和后续人工编辑 |
| text-based diagram | 目标输出表面能够显示等宽文本 | 命令行界面（Command-Line Interface，CLI）或纯文本环境中的结构关系 |
| HTML/CSS | 能够交付并打开 HTML Artifact | 交互、复杂排版或组合多个视觉组件 | |


## 选择图形

| 需要表达的关系 | 合适表达 |
|---|---|
| 数据流、管线 | flowchart、分层流程图、简短文本箭头 |
| 时序交互 | sequence diagram、泳道、按时间排列的箭头 |
| 生命周期、模式切换 | state diagram、状态地图 |
| 对象、类型、数据结构 | class diagram、entity relationship diagram、对象框图 |
| 责任、平台、验证或证据边界 | 区域图、泳道、subgraph |
| 对比、取舍、覆盖关系 | 表格、矩阵、并列区域 |
| 时间线、计划 | timeline、Gantt chart |


## 视觉质量

精美来自清楚的层级、稳定的对齐、充足的留白和克制的视觉语言，而不是装饰数量。让标题、分组和阅读顺序一眼可辨；保持字体、形状、线条和颜色的语义一致。使用有限且协调的配色，颜色用于区分类别、状态或重点，不承担唯一信息。

一个图只承担一种主要关系。复杂主题使用多张相互协调的视图，不把所有信息挤进一张图。边界、方向或连线含义不明显时，使用明确标签；避免交叉线、遮挡、重叠、过小文字和无意义图标。

使用目标载体的渲染能力，使用户能够直接看到图示。完成前检查文字、布局和关系是否清晰。

图内文字以用户语言为主，标准术语保留原文。
