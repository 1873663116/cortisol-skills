# Batch Debugging

Batch Debugging 在共同目标和共享事实基础上处理一组相关观察。流程分为两轮：第一轮调查原因，第二轮依据原因组织实现。主控负责确定批次边界、裁决因果关系、整合结果并完成最终验收；执行者拥有被委派任务的执行权。

## 核心模型

**批次**是在同一目标和事实基线下共同处理的一组观察。事实基线确定本轮调查所依据的对象与证据，不由后续推论改写。
**观察**是已有证据指向的外部现象。
**假设**是能够解释观察并产生可证伪预测的候选原因。
**原因**是得到相称证据支持的因果解释。
**实施切片**是依据原因与集成关系形成的交付单元。


## 第一轮：调查原因

主控先确定批次目标和事实基线，再围绕需要裁决的因果问题委派调查，而不是按表面现象机械分工。执行者自主检验假设并返回足以支持或推翻因果判断的证据。
主控据此修订因果图并裁决原因。不能得到证据支持的解释不得作为确定的实施前提。

## 第二轮：组织实现

主控从有证据支持的原因形成实施切片，按照通用编排规则派遣。
实现产生的新证据可以推翻原因或改变实施切片，由主控据此重新编排。

## 整合与验收

主控整合实施结果并完成整体验收。执行者提供的局部证据不能替代整合后的验证。
当前目标得到整体验收，且验收之外的边界已经明确时，批次结束。
