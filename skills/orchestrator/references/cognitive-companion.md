# Cognitive Companion

Orchestrator 的认知分支。它用现有 Model 校准与用户的协作，并把高频、临时的工作认知与低频、由用户拥有的 Model 分开。



## 认知基线

个人 Wiki 位于 `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/wiki`，是用户认知结构的外部表示。当规划、架构、诊断解释、教学、方案选择或认知考核需要了解用户当前理解到什么程度时，读取 Wiki 的 `AGENTS.md`


## 捕捉

发现用户形成了新的关系、暴露了疑问或矛盾、项目证据挑战既有理解，或出现候选认知核心时，创建当前 Thread 独占的 Cognitive Ledger。Ledger 是项目内私有、Git 忽略的临时运行记录；位置服从项目规则。它只保留用户表达的新理解、明确问题或矛盾、项目证据指针和候选后续动作。

纯执行、机械修改和既有理解的直接应用不创建 Ledger。
Ledger 在过于巨大、过于繁杂时，需要作合并性地重建。

Ledger 的条目是待检验信号，不是 Model 增量，也不是 Cognitive Debt。


## 派生考核

在准备实现、阶段结束或 Thread 结束时，或用户主动要求考核时，若 Ledger 中存在值得检验的材料，使用 `fork_thread` 从当前 Thread 分叉一个认知考核 Thread，让项目主 Thread 继续执行。派生时标记当前 Ledger 为该分支独占的 Checkpoint；源 Thread 因此明白自己应该停止写入它，之后只有再次出现真实认知信号时源 Thread 才惰性创建新 Ledger。

考核 Thread 不允许创建 Ledger。

考核在不读取 Model 的情况下，请用户从项目情境中重新讲述关键结构、因果和判断依据；然后才按完成可靠比较所需的范围读取 Wiki 与现有 Model。先盲测可以避免现有表述暗示答案；后读 Model 同时允许复习、去重和结构比较。

用户的参与有限且可撤回。拒绝、沉默、跳过和不完整回答只表示没有获得证据，不表示理解缺失；未回答且没有缺口证据的题目默认丢弃，只在用户明确要求时保留。追问应服务于消除真实歧义或当前项目正确性，并随用户退出而收束。

## 比较与收束

考核结束后，认知考核 Thread 读取相关 Model，只比较用户实际回答或已有明确证据的内容，然后依次处理：

1. Model 已经覆盖且没有矛盾的内容只算完成复习，不写回。用户未回答、跳过或要求删除且没有其他缺口证据的内容直接丢弃。
2. 用户已经表达清楚、但 Model 尚未记录的新内容、纠错或结构改进，形成 Model 变更候选。
3. 只有用户确实无法解释或应用某项理解，或者明确承认仍有疑问时，才记录 Cognitive Debt。Model 没写到某项内容、用户回答不完整或尚未确认变更，都不能单独证明存在 Cognitive Debt。

获得所需确认后，认知考核 Thread 直接读取 Wiki 的 `AGENTS.md`，按照其中的规则修改 Wiki 并核对结果，不再创建或委派另一个 Thread。

所有已有证据的内容都已归类，允许的 Wiki 修改也已完成时，删除 Checkpoint。若仍在等待用户确认或 Wiki 修改失败，保留 Checkpoint，并明确说明尚未完成的事项；用户拒绝保存或要求删除时，丢弃相应内容并清理。
