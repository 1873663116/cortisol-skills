# Orchestration

当默认的主控与 Sidekick 组合不足时，本协议用于扩展执行拓扑。`SKILL.md` 中的委派、等待和验收规则同样适用于这里的每个扩展分支。


## 扩展执行拓扑

- **额外 Subagent** 承担可以与 Sidekick 或其他工作并行推进的有界分支，完成后把结果、证据和产物返回主控。
- **额外 Thread** 是 Sidekick 之外具有独立身份和生命周期的持久工作流。它可以持续接收指令、容纳用户参与、派遣自己的 Subagent，并在主控当前阶段结束后继续存在。

工作量本身不决定载体。只服务于当前主控且边界明确的并行工作交给额外 Subagent；值得拥有独立于 Sidekick 的身份，并需要暂停、恢复、让用户参与或继续调度的工作交给额外 Thread。

依赖关系决定串行或并行：需要上一分支结果才能定义的问题串行推进；目标与写入边界相互独立的分支可以并行。大规模并行是按任务结构扩展的能力，不改变长期 Sidekick 的身份。

**完成条件：** 每个扩展分支都有独立目标、清楚的输入依赖、返回关系和符合其生命周期的载体。

## 管理额外 Thread

- 已有额外 Thread 的目标、身份和上下文仍适合当前工作时，继续该 Thread 或向它补充指令。
- 工作需要新的持久身份，且现有上下文会实质改变执行结果时，从相应 Thread 分叉。
- 工作需要新的持久身份，但不依赖现有 Thread 历史或必须进入另一项目环境时，创建 Thread。

**完成条件：** 每个使用中的 Thread 都有明确的持续身份、当前目标和与主控的返回关系；新建或分叉只发生在需要新生命周期时。

## 安排执行现场

依赖决定串并行，写入碰撞、独立 Revision、集成归属和实验基线决定是否使用 Worktree。委派时直接提供绝对工作路径、revision、所有权、已有证据、目标和返回合同；项目与工具的通用常识由承担该分支的 Agent 自行获取。

本地执行涉及共享、不可隔离或互相干扰的资源时，读取并服从项目定义的本地协调协议。远程执行与可安全并行的验证依据其自身运行环境调度。

**完成条件：** 每个扩展分支都获得会改变结果的最小充分现场，写入边界和依赖关系清楚，本地共享资源已路由到适用的项目协议。

## 监督、整合与收束

主控维护所有扩展分支之间的依赖、写入所有权和返回状态。并行结果返回后，主控核对产物、相互作用和项目要求的验证证据，再决定继续调查、统一集成或停止相应分支。

已经验收并整合的临时执行 Thread 可以归档。失败 Thread 在证据与未决问题被完整接收后归档。仍需用户参与、继续执行或由项目指定持久存在的 Thread 保持可用。

**完成条件：** 所有派生工作都有已知状态，整合结果满足当前证据门槛，已结束 Thread 的知识和产物得到接收，仍需延续的 Thread 保有明确下一步。
