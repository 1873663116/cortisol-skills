# Orchestration

这是 Orchestrator 管理派生工作的通用协议。主控保留目标、关系、证据、选择和集成状态组成的控制面；派生 Agent 承担调查、实现与验证等执行工作。主控根据现场决定执行拓扑，并向用户披露有实质影响的安排，不逐项请求工具选择。

## 选择执行者

- **Subagent** 是主控拥有的内部执行单元。它承担有界工作，完成后把结果、证据和产物返回主控，不需要独立延续。
- **Thread** 是具有独立身份和生命周期的持久工作流。它可以持续接收指令、容纳用户参与、派遣自己的 Subagent，并在主控当前阶段结束后继续存在。
- **主控执行** 用于必须由全局上下文持有者完成的裁决与整合，以及委派成本高于上下文影响的窄幅工作。

工作量本身不决定执行者。完成后只服务于当前主控的工作交给 Subagent；值得独立暂停、恢复、参与或继续调度的工作交给 Thread。主控结合工具输出、运行时注入和局部上下文对控制面的影响，决定是否亲自执行。

**完成条件：** 每项准备推进的工作都有符合其生命周期的执行者，主控保留完成整体目标所需的上下文。

## 使用 Thread

Thread 是调度对象；继续、创建和分叉是它的生命周期操作：

- 已有 Thread 的目标、身份和上下文仍适合当前工作时，继续该 Thread 或向它补充指令。
- 工作需要新的持久身份，且现有上下文会实质改变执行结果时，从相应 Thread 分叉。
- 工作需要新的持久身份，但不依赖现有 Thread 历史或必须进入另一项目环境时，创建 Thread。

主控在已获授权的目标范围内自行选择这些操作，并持续负责派生 Thread 与整体目标的关系。

**完成条件：** 每个使用中的 Thread 都有明确的持续身份、当前目标和与主控的返回关系；新建或分叉只发生在需要新生命周期时。

## 安排执行现场

依赖决定串并行，写入碰撞、独立 Revision、集成归属和实验基线决定是否使用 Worktree。委派时直接提供绝对工作路径、revision、所有权、已有证据、目标和返回合同；项目与工具的通用常识由执行者自行获取。

本地执行涉及共享、不可隔离或互相干扰的资源时，读取并服从项目定义的本地协调协议。远程执行与可安全并行的验证依据其自身运行环境调度。

**完成条件：** 每个执行者都获得会改变结果的最小充分现场，写入边界和依赖关系清楚，本地共享资源已路由到适用的项目协议。

## 监督、整合与收束

主控持续掌握派生 Thread 与 Subagent 的状态，把失败、阻塞、超时和复核请求作为需要判断的信号，并依据证据决定继续、调整、停止或重新派遣。派生工作返回只表示该执行单元结束；主控核对产物、选择、相互作用和项目要求的验证证据后再整合。

已经验收并整合的临时执行 Thread 可以归档。失败 Thread 在证据与未决问题被完整接收后归档。仍需用户参与、继续执行或由项目指定持久存在的 Thread 保持可用。

**完成条件：** 所有派生工作都有已知状态，整合结果满足当前证据门槛，已结束 Thread 的知识和产物得到接收，仍需延续的 Thread 保有明确下一步。
