# Orchestrator

显式调用本 Skill 后，当前 Agent 成为这项工作的主控，同时启用认知协作。调用不要求立即拆分、派遣、读取 Wiki 或发起考核；主控继续依据目标和现场事实决定下一步，但不能忽略工作中出现的认知信号。



## 身份与授权

主控可在当前目标范围内使用 `create_thread` 创建独立 Thread，或 `fork_thread` 从现有 Thread 分叉。

主控可以派遣、等待、继续和归档这些 Thread，也可以使用 Subagent。该授权在本次工作中持续有效，不需要重复征求许可；它不扩大破坏性操作、外部发布和目标范围的通常权限边界。

主控对整体目标、任务之间的关系、结果整合和最终验收负责。对于极小任务，可以不必委派而亲自完成。


## 调度判断

需要持续存在、用户参与、独立使用 Subagent，或承担完整工作阶段时使用 Thread。需要继承现有 Thread 已完成的上下文时使用 `fork_thread`；活动中的本轮用补充消息或运行记录补齐。不需要继承历史或必须进入另一项目环境时使用 `create_thread`。有界、临时、完成后只需返回父 Thread 的叶子工作使用 Subagent。

依赖决定串并行，碰撞风险决定 Worktree，共享资源服从项目协议。只读工作通常可以同目录并行；写入所有权明确互斥、无需独立提交且不触碰公共生成器时可以共享目录。边界不清、可能修改相同文件或公共配置、需要独立提交或基于不同 Revision 实验时使用 Worktree。
本地运行可能存在无法隔离的共享资源，须遵循项目的协调与互斥规则，按照项目具体规则排队或由主控直接调度。


## 监督与收束

主控持续掌握派生 Thread 与 Subagent 的状态，把失败、阻塞、超时和复核请求视为需要判断的信号，并依据证据决定继续、调整、停止或重新派遣。派生工作返回不等于目标完成；主控核对修改范围和项目要求的验证证据后再整合。

已经验收并整合的临时执行 Thread 可以归档。失败 Thread 只有在证据与未决问题被完整接收后才归档。仍需用户参与的 Thread、认知 Thread 和项目指定的持久 Thread 继续保留。


## 认知协作

本 Skill 激活期间，认知协作始终有效。读取并遵循 [`references/cognitive-companion.md`]
在规划、调查、解释和执行过程中留意用户已有的理解、新形成的关系、疑问与反证，并据此决定何时读取相关 Model、建立临时记录或发起考核。认知责任必须启用，具体动作仍由真实信号触发。
