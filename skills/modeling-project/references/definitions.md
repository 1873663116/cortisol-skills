# 定义

这些定义用于本技能的状态判断与项目资料。项目可以根据实际任务补充约定。

| 术语 | 定义 |
| --- | --- |
|  |
| 宏观设计 | 项目的表达动机、体验目标、观看方式、主要构图、整体尺度、视觉意向与已确认约束。尚未决定的内容作为设计问题记录。 |
| 微观架构 | 场景中的具体物件和部件的构成、关键尺寸、连接与安装关系、采用的参考、形体来源及低高模对应。材质、灯具等局部要求归入对应物件；复杂内容按需拆分并由本文导航。 |
| 项目地图 | AGENTS.md 中通向有效文档、活动工程、资产来源及必要工具的索引，附项目操作约定。具体参数保存在被索引的权威资料中。 |
| 物件 | 能作为一个实际对象理解、移动和检查的组合，例如凳面、凳腿和脚踏环组成一张高脚凳。部件保持可编辑，通常通过父级与集合组织。可以是单个或多个mesh。 |
| 部件 | 物件中承担独立构造或表面作用的组成部分，通常是单个mesh。 |
| 探索底模 | 用于判断比例、构图与形体的低成本三维表达，允许快速替换。 |
| 硬表面细分 | 能通过边折痕来控制细分修改器 (Catmull) 对低模大形的剧烈改变。 |
|  |
|  |
| 设计依据 | 本次任务采用的尺寸、SVG、参考图、粗模或明确约束。每项依据说明适用范围；尺寸冲突在依赖它的制作前解决。 |
 |
|  |
|  |
|  |
| 公共资产 | 位于单个项目之外、已整理用于复用的模型、材质、节点或资源；保留来源、版本及必要依赖。 |

三个低密度表示可以共享来源。简单物件可以由同一网格承担探索、细分控制和输出职责；需要不同拓扑时保持形体来源可追溯。

用户对设计的认可决定表达方向；实现的验证状态由实际检查确定。候选结果用于比较选择，其制作权限来自本次任务。
