### 运行时取证（Runtime forensics）

**对运行时故障诊断负全责。针对活跃运行的进程进行动态插桩，严禁脱离运行时对着源码凭空猜测。** 适用于排查“进程为何在运行时发生内存泄漏、CPU 异常空转或周期性变慢”、分析堆内存快照、排查表面空闲实则高负荷的后台进程，以及定位间歇性偶发故障。核心交付物为附带确凿证据的深度诊断报告，而非直接修复代码。

1. **在真实运行界面采集实时动态信号。** 通过控制类技能在匹配的宿主环境下采集第一手真实数据：CPU 异常空转采集 CPU Profile，内存泄漏抓取堆内存快照（Heap Snapshot），UI 渲染抖动采集 Chrome DevTools Protocol（CDP）Trace。一切以真实采集产物为准，严禁凭空揣测。
2. **将分析聚焦收敛至核心铁证。** 准确定位热点调用链中的关键函数、追踪从泄漏对象直达 GC Root 的强引用链，或找出在无外部输入时仍持续空转触发的死循环。超大体积的分析产物交由子 Agent 解析（遵循**守卫上下文窗口**原则），主线程仅保留提炼收敛后的核心结论。
3. **在采纳任何故障机理假设前必须先完成闭环验证。** 通过 CDP Runtime Evaluate 动态向运行中的活跃进程注入插桩探针，或在不重启进程的前提下热替换运行中的代码，以极低成本对假设进行实测求证。看似合理但未经验证的推测往往全盘皆错，而真实的病因很可能潜伏在相邻的架构层次中。
4. **将问题机理精准映射至源码位置。** 明确指出具体的文件路径、符号名称，以及触发异常分配或异常调度的关键代码行。
5. **记录简化检查点。** 吞吐检查点单行记录为 `throughput checkpoint: n/a, read-only forensics`。

**最终回复要求：** 捕获的关键信号特征、收敛提炼后的核心诊断结论、针对该故障机理的具体证明过程、源码精确定位、分析产物文件存储路径。除非用户显式要求，否则不提供修复代码；根本原因查明后交由缺陷修复（Bug fix）或性能问题（Perf issue）流程承接。
