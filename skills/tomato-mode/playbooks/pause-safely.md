### 安全暂停（Pause safely）

**对干净优雅地暂停当前会话负全责。留下一个让冷启动（Cold-start）Agent 能够无缝续接的检查点。** 适用于“安全暂停”“我要下线了”“准备重启 Cursor”“我要上飞机了”，以及会话上下文即将被压缩或生成摘要的场景。本流程仅在收到明确暂停指令或发生环境收尾事件时触发。遇到“继续做”“我去睡了，你接着跑”“别停下”等指令时严禁暂停——这些属于继续授权，且自主运行 playbook 本身会在每次迭代中自动记录检查点。

1. **停在安全的事务边界上。** 将当前正在执行的原子步骤完整做完，或者干脆彻底回退至上一个干净状态。严禁在代码处于半途破损、无法通过基本校验的中间状态下随意暂停。停止启动任何新任务，并立即取消所有正在运行的嵌套子 Agent。
2. **暂停操作严禁越过不可逆的安全红线。** 除非本轮任务此前已经正式发起了 PR，否则在暂停流程中严禁新建 PR，严禁向远程分支执行 push。
3. **确保本地工作完整持久化。** 将所有尚未提交的有效改动统一作为语义清晰的 `wip:` commit 提交至当前本地分支，确保无任何改动丢失。若当前 Worktree 处于破损状态，在 commit message 正文中用单行简要说明。
4. **将续接上下文说明固化到外部介质中。** 详细记录原始意图、暂停时正在进行的操作、当前进展与已验证事项、系统当前状态、明确的下一步计划、核心关键文件清单以及已知陷阱与注意事项。由上下文压缩触发的场景必须将说明写入独立文件（例如 `/tmp/<slug>-resume.md`），因为留在 LLM 上下文窗口中的计划无法跨越摘要压缩幸存。若当前已有维护中的 show-me-your-work 决策轨迹文件，直接指向该文件即可，严禁冗余复制。

**最终回复要求：** 当前在执行循环中所处的具体阶段、已持久化到磁盘的内容 vs 仅停留在内存中的上下文（提供具体文件路径，严禁直接贴大段 diff）、已提交的 commit 清单与 Worktree 干净程度状态、恢复续接后的首个立即执行动作。本次回复属于暂停状态通报，而非最终交付报告；后续将由“会话接手（Session pickup）”playbook 读取此说明。
