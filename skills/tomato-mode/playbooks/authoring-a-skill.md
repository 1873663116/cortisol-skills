### 编写或修改技能

**把控技能的文风与基调。** 面向 Agent 的指令文档比面向人类的文档要求更高：任何无实质指导意义的冗余文本都可能被 Agent 误读为强制执行的指令。

1. 调用 **writing-for-agents** 技能。阅读其中关于技能机制的章节，了解 frontmatter、调用方式与路由规则。
2. 校验技能定义：frontmatter 必须包含 `name` 和 `description`，引用的文件真实存在，跨技能链接能够正确解析。
3. 涉及结构性约束的改动编写自动化测试用例；纯主观经验类规则可跳过写测试。
4. 执行**开 PR**。

若存疑则坚决删除；每一段文字都必须能够切实改变某项技术决策，方有存在的必要。直接给出具体行动指令，省去无关的理由说明。仅在缺少背景会导致规则理解产生歧义时才附带简要解释。文风基调应与任务范围相符。优先指向结构化权威来源（类型定义、README、配置文件等）；硬编码的细节极易陈旧失效（遵循**将教训沉淀进系统结构中**原则技能）。通过文件路径直接委派给其他技能，不要原地复述。若发现反复出现但尚未规范化的工作流，则提议沉淀为新技能。

**最终回复要求：** 技能概述、核心设计决策、校验记录说明。
