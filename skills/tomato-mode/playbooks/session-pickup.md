### 会话接手（Session pickup）

**对平滑续接上一个会话负全责。深度研读前序 Agent 留下的决策记录与上下文，严禁无脑推倒重做。** 适用于“接手这项任务”“继续这个会话”“从 <历史记录路径> 继续推进”“由你接手跟进”“从前序 Agent 停下的地方继续”、云端 Agent 的 URL 状态交接，或承接一条需要继续推进的已推送远程分支。

接手本质上是继承。前序 Agent 已经付出了通读代码、构造复现用例、完成架构选型的高昂成本。推倒重做不仅会丢失已获得的偏离校验基准，还会急剧白白消耗上下文窗口。必须克制住重新推导一切的冲动，认真精读既有记录。

1. **定位并解析前序 Agent 的执行轨迹。** 来源可能为当前工作区 `<slug>` 目录下的本地会话记录 `~/.claude/projects/<slug>/<uuid>.jsonl`（严禁使用 `~/.claude/projects/*/` 进行全局通配，以免越界读取其他项目的历史会话；当前工作区 `/Users/xiongzhipeng/.agents` 对应目录为 `~/.claude/projects/-Users-xiongzhipeng--agents/`）、云端 Agent 的 URL 状态，或一条已推送的 Git 分支。先快速阅读元数据摘要与最后数条消息，再向前倒推关键技术决策点。超长会话记录委派给子 Agent 解析，主线程仅保留提炼后的时间线纪要（遵循**守卫上下文窗口**原则）。
2. **精准重建当前工作空间与 Git 状态。** 核查当前分支与 Worktree 状态、已正式落地的改动（`git log`、对比基线分支的 `git diff`）、尚未完成的待办事项、已敲定的架构决策。前序记录属于权威输入，必须克制住从零重新推演的冲动。
3. **精确比对已完成工作与剩余待办项。** 将当前已交付物与初始规划进行严格比对，明确界定当前续接切入点，严禁重跑前序已稳定的复现用例，严禁重做已完成的工作。“让我从头全量验证一遍”等盲目行为表明你错误地将权威的历史记录当成了不可信数据。
4. **将剩余工作路由至匹配的 Playbook 并明确裁决方式。** 选定后续执行策略：继续执行既定计划、输出完整的方案建议、批准或纠偏此前的中间结论，或针对失败的执行记录进行复盘。本接手流程在此处闭环收敛，后续任务由被路由的具体 Playbook 负责推进。
5. **在真实运行产物上对继承的关键结论进行端到端抽检。** 严格对照原始需求目标，在真实产物上验证关键结论（遵循**用实际运行证明有效**原则）；前序 Agent 自身的单方自述通过不得等同于真实证据。

**最终回复要求：** 前序 Agent 停滞的具体位置、已继承的内容 vs 重新验证/调整的内容（理想情况下无需任何推倒重做）、当前接续切入点、最终执行结果。
