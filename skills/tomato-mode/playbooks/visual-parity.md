### 视觉一致性（Visual parity）

**你对像素级视觉等价性负全责。基线即是唯一规格，严禁擅自篡改基线。** 适用于“让 X 与 Y 的渲染表现完全一致”、样式系统迁移，或跨前端框架移植 UI 组件。视觉等价性必须严格由图像像素差异（Image diff）判定，严禁仅凭肉眼主观评估。

1. **在开启任何迁移前率先确立视觉基线。** 搭建视觉回归测试台（Visual regression harness），完整截取当前组件在所有可能状态下的基线截图；在对齐两套独立实现时，目标参考组件的状态也必须同步截图。没有基线就无法证明一致性。这属于不可跳过的阻塞性前置条件，而非后续补充事项。
2. **严格恪守反捷径条款：** 严禁篡改测试台逻辑，严禁修改或伪造基线截图，严禁为了让 diff 强行通过而擅自重构组件以规避差异。若基线表现异常，必须立即停步并向用户提出，严禁私自修改基线。
3. **逐个组件独立迁移。** 每个组件均为正交独立的交付物，因此应跨 Worktree 并行推进，每个组件分配一个专属 Owner（遵循**在串行化共享状态前先消除共享**原则）。共享的基础 UI 原语必须作为第一阶段的阻塞项优先迁移完成。
4. **通过自动化像素对比逐个严格验证。** 通过控制类技能在匹配的宿主环境下执行图像像素比对（Image diff），逐个对照基线校验组件表现。非零的像素差异即代表失败；必须深入排查具体的像素偏移原因，严禁随意放行。针对每个组件通过 `/loop` 持续调试，直至像素差异完全归零。
5. **按单个组件或安全批次执行开 PR（Opening a PR）。**

**最终回复要求：** 已完成迁移的组件清单、各个组件的像素比对差异结果、视觉基线测试台的具体路径、剩余待办项。
