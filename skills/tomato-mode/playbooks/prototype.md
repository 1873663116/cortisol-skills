### 原型（Prototype）

**你负责的是架构与交互设计决策，而非生产级代码。原型是用完即弃的探索工具，正式构建请走功能开发流程。** 适用于“做个原型验证”“搭个 mock 看看效果”“草拟一个实现”“试试这种布局”，以及在正式敲定前探索全新的 UI 渲染、交互模式或布局架构。亦适用于通过观察实际运行效果来终结经验性技术分歧（如抉择采用何种行为模式、具体时序策略或工程实现路径）——即那些你原本打算询问人类、但一个快速原型探针就能直接给出答案的问题。

本 playbook 是唯一将极简工程原则中的“最小改动”与严格代码验证要求反转适用的场景。此处的首要目标是速度而非代码打磨，无需关注代码整洁度，无需编写冗长规划。其工程严谨性体现于以极低成本筛选出正确的设计方向。应大胆探索，主动构思用户未曾明确提及的备选方案，敢于随时推翻已有尝试并换用新方案。

1. **圈定原型旨在解决的核心决策。** 明确该原型究竟要验证什么：选哪种布局、哪种交互流程、哪种信息密度；在经验性技术分歧中，则是厘清哪种行为契约、何种时序调度或哪种技术选型最为合理。若不存在需要抉择的未决问题，严禁无目的构建原型，直接路由至功能开发流程。
2. **在设计空间开放时广泛收集参考案例。** 检索现有的成熟设计与实现模式，汇总一份包含设计主题、色彩搭配与布局构架的灵感面板（Mood board），供用户在动手前快速确认大方向。若方向已完全明确则跳过本步。
3. **在隔离的临时目录中快速构建一次性实现。** 严格与生产源码隔离。针对 UI 视觉与交互决策，使用原生 HTML/CSS/JS 或能够渲染出该想法的最轻量技术栈，外部依赖通过 CDN 加载，启动带有热更新的本地开发服务器；针对后端行为或时序决策，编写能够触发该场景的最小独立验证脚本。严禁引入重型生产框架，不写测试用例，不搞复杂抽象。
4. **并列对比多个备选方案。** 将多个方案集成在同一个快速切换控件下（如切换按钮或快捷键），为每个方案变体打上清晰标签，方便用户逐一体验与指名比选。这正是**穷尽设计空间**原则在低成本探索场景下的具体实践。
5. **在匹配的宿主界面上验证。** 针对 UI 视觉决策，通过控制类技能为每个变体截取实际渲染图并驱动交互，肉眼即是验证工具；针对行为与时序决策，直接观察目标变量的实时表现，记录精准时序日志或打印输出。此处的验证手段是客观观察，而非写自动化断言。
6. **输出方案对比、利弊权衡与明确推荐。** 最终交付物为清晰的技术决策结论及配套的一次性验证产物，绝非可直接上线的生产代码。将确立的最终方向交由**功能开发（Feature）**进行正式工业级构建（若涉及复杂数据结构或模块划分，则交由 `architect` 技能）。

**最终回复要求：** 已探索的方案变体清单、实测客观证据（视觉决策附真实截图，行为决策附捕获的输出或时序数据）、各项方案利弊权衡、你的最终技术推荐，以及临时原型目录的绝对路径。明确注明该原型代码属于用完即弃的探索产物。
