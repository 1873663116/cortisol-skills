### 性能问题（Perf issue）

**对性能度量与优化依据负全责。严密规划、代码审查、严格核对量化数字。** 每一处性能修复都必须严格挂钩确凿的测量数据，严禁用肉眼走读源码替代实测。

1. **采集基线数据。** 通过对应的控制类技能在真实宿主环境下采集一份完整的基线性能分析轨迹（baseline trace）。
2. **基于系统机理提出优化假设。** 调用 `how` 技能透彻理解目标模块的底层执行链路。未完成实测前，严禁妄断系统性能已达瓶颈极限。
   绝大多数性能优化归属于以下八大策略族。应将它们视为假设生成器，而非生搬硬套的检查清单。仅当性能分析轨迹（trace）明确显示出某一族对应的特征信号时，该策略才值得付诸尝试；针对核心主导开销的单点深度优化，效果远胜于八种手段全上的浅层堆砌：
   - **消除（Elimination）。** 成本最低的代码是根本不运行的代码。在优化热点路径前，先质疑其存在的必要性。它可能是无下游消费的冗余计算、对当前类型用户永远禁用的特性分支、冗余镜像状态的同步操作，或是“以防万一”遗留的废弃链路。性能分析工具（profiler）只能指出哪些逻辑耗时较长，无法指出哪些逻辑可以直接删除，因此该策略依赖对 `how` 架构走读的透彻理解。凡是适用消除的场景，直接删除该部分工作远胜于任何其他优化手段。
   - **分而治之（Divide and Conquer）。** 核心主导开销随输入规模急剧膨胀。将大任务切分，使每个细分子任务触碰更少的数据（如分块、分片、剪枝排除无关搜索空间），或让彼此正交独立的部分并发执行。
   - **缓存（Caching）。** 针对相同输入的相同昂贵计算或数据拉取重复发生。将计算结果持久化暂存以供复用。在宣称优化生效前，必须先明确定义并验证其失效策略与边界条件。
   - **解耦层与间接优化（Indirection）。** 热点路径正在执行某些可通过低成本中间层吸收的昂贵操作。使用索引替代全量扫描，引入异步任务队列将阻塞操作移出交互主线程，运用轻量句柄（handle）解耦以便动态替换为更高效的底层实现。仅当引入该间接层从关键路径上卸载的耗时显著大于其自身带来的固定开销时方可引入；处于热点路径上却未减少任何实际工作量的中间层纯属纯粹的性能负债。
   - **批处理（Batching）。** 大量细碎的小操作各自承担高昂的固定开销（如网络 RPC、数据库查询、系统调用、图形 draw call）。将它们打包聚合，每批次仅支付一次固定开销。
   - **冗余与对冲（Redundancy & Hedging）。** 任务等待卡在个别慢实例或偶发延迟毛刺上。复制发起多份相同任务（如副本查询、对冲请求、投机执行），采纳最快返回的结果。这是用额外的系统吞吐负载换取更低的长尾延迟（tail latency），因此必须满足 trace 显示等待耗时占主导且系统尚有算力余量的前提。脱离该权衡前提的盲目复制只会加剧系统拥堵。
   - **惰性求值与按需加载（Lazy Evaluation）。** 开销发生在从未被实际消费、或当前暂不需要的数据结果上（如启动路径上的过早初始化、视口外 DOM 节点的渲染）。将这部分计算推迟至首次被实际请求时才触发。
   - **时序错峰与后台调度（Scheduling）。** 该工作必须执行，但不必在用户交互的黄金瞬间同步阻塞执行。将其移至无人在等待的时段，例如利用浏览器空闲回调（idle callbacks）、应用启动后的后台预热、用户到达前的预先计算、或帧提交后的异步清理。与惰性求值（按需触发）不同，错峰调度通常将工作安排在交互高峰*之前*或置于后台阴影中运行。其优化目标是前端感知延迟，因此必须针对交互关键路径进行度量，而非统计全量总工作量。
3. **基于 Trace 规划并实施修复。** 若改动跨越函数边界，先调用 `architect` 技能。阅读 **dispatch** 技能规范选定 `Letter-precise` 角色，经 **orchestration** 技能派发具体编码实现并审查生成的 diff。随后采集修复后的全新性能分析轨迹（trace）。
   严格遵循**将工作划分为闭环可验证单元**原则，每次尝试均经过完整验证后再进行下一次尝试。
4. **深入比对量化产物。** 解析并深入比对修复前后的两份性能数据（例如将 trace JSON 转为 SQLite 进行差异查询 diff）。“结论不确定”或在错误的测试界面上运行均不得视为通过，必须如实标明。
5. **在 PR 中附带完整的量化测量证据。**
6. **执行开 PR（Opening a PR）。**

若需要针对特定指标进行持续、多轮的闭环优化，而非单次问题排查修复，请使用爬山优化 playbook（`playbooks/hillclimb.md`）。

**最终回复要求：** 基线测量数值、优化后测量数值、绝对与百分比差值、性能分析产物文件的具体存储路径。
